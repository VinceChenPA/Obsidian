# LLM Wiki 中文实践指南

> 整理自 [[03.Engineering/Common_Area/AI/llm-wiki|LLM Wiki]]（原文保留作来源），结合本库（Obsidian vault）的落地实践。核心目标：让 LLM 增量维护一个持久、复利增长的个人知识库。

## 核心思想：拒绝"每次重新检索"

| 模式 | 工作方式 | 问题 |
|---|---|---|
| RAG | 提问时才从原始文档检索片段、现场拼合答案 | 知识不累积，每次从零综合 |
| LLM Wiki | LLM 把新来源**消化进**结构化 wiki，更新实体页、修订摘要、标记矛盾 | 知识编译一次、持续保鲜 |

**例子**：同一个问题需要综合五篇文章才能回答——
- RAG 模式：每次提问都要重新找到并拼合五个片段，结果不沉淀；
- LLM Wiki 模式：第一篇文章入库时摘要已写好，后续文章的矛盾之处已被标记，提问时直接读最新综合页。

**人机分工**：人负责选来源、探索、提问；LLM 负责摘要、交叉引用、归档、记账。Obsidian 是 IDE，LLM 是程序员，wiki 是代码库。

## 三层架构（含本库对应）

| 层 | 职责 | 本库对应 |
|---|---|---|
| 原始来源 | 不可变的真相来源，LLM 只读 | `99.Attachments/`、外部文章的原始剪藏 |
| Wiki | LLM 生成与维护的 markdown 页面 | `00.*`–`06.*` 笔记 + 各 `MOC.md` 索引 |
| Schema | 结构约定与工作流定义 | `AGENTS.md`（五键 frontmatter、tag 体系、Ingest/Query/Lint 工作流） |

## 三种工作流

### 1. Ingest（摄入）

本库标准步骤（见 `AGENTS.md`）：读取来源 → 确认要点与归属 → 写主题笔记 → 更新对应 `MOC.md`（摘要 + wikilink）→ 更新受影响页面 → 清理收件箱 → 记 `log.md`。

**例子（真实）**：2026-09-13 拉取到 `llm-wiki.md` 后——
- 与用户讨论要点后，在本目录新增本笔记；
- 在 `AI/MOC.md` 补条目：`[[03.Engineering/Common_Area/AI/LLM-Wiki-中文实践指南|LLM Wiki 中文实践指南]]`；
- 在 `log.md` 记录本次 ingest；
- 原文不动，作为来源保留。

一次 ingest 触及 5 个以上页面是常态，这正是"知识复利"的来源。

### 2. Query（提问并将答案归档）

对 wiki 提问，LLM 检索页面、带引用作答；**值得保留的答案要归档回 wiki**，不让结论消失在会话记录里。

**例子（真实）**："如何在 Obsidian 库中应用 llm-wiki 的最佳实践？"
- 得到的四条建议没有停留在聊天里：Ingest/Query 工作流写进 `AGENTS.md`、Lint 做成 `vault-lint` skill、`log.md` 落地在根目录；
- 本轮问答的产物就是你现在读到的这篇笔记。

### 3. Lint（健康检查）

**检查清单**
- 内容层：页面间矛盾、被新来源取代的过时断言、可用搜索补齐的数据缺口
- 结构层：孤儿页（无入链）、被反复提及但无独立页的概念、缺失交叉引用、死链、MOC 遗漏
- 规范层：frontmatter 五键完整、tag 含 `type/*` 且无空格、wikilink 带路径形式

**例子（真实）**：2026-09-13 首轮 lint 扫描 98 个文件，发现 26 篇无 frontmatter、47 篇缺 `updated`、1 处死链、4 处 MOC 遗漏；随后批量修复 78 篇 frontmatter、41 篇补 H1、清理死链，复检全绿。

## 最佳实践清单

1. **索引先行**：查资料先读索引（本库 `Home.md` → `MOC.md` → 具体笔记），避免全库翻找。
2. **好答案归档**：对比表、新连接、分析结论都是资产，写回对应笔记或 MOC。
3. **一次摄入、多页联动**：新来源往往要更新摘要、实体页、概念页、索引、日志等 10+ 页。
4. **矛盾显式标记**：新来源推翻旧结论时保留旧观点，标注"已被 XX 取代"，而不是静默删除。
5. **log 用可解析格式**：`## [YYYY-MM-DD] <操作> | <说明>`，`grep "^## \[" log.md | tail -5` 即可看近期动态。
6. **LLM 写、人读**：交叉引用、摘要同步这类维护性内容交给 LLM，人专注来源与判断。

## Obsidian 技巧

| 技巧 | 用法 | 本库现状 |
|---|---|---|
| Web Clipper | 浏览器剪藏文章为 markdown 进收件箱 | 推荐：剪藏后走 Ingest 消化 |
| 图片本地化 | 附件目录设为 `99.Attachments/`，绑定"下载附件"快捷键 | 已具备 |
| 关系图谱 | graph view 识别枢纽页与孤儿页，是 lint 的直观辅助 | 已具备 |
| Marp | 从笔记直接生成演示幻灯片 | 按需启用 |
| Dataview | 基于 frontmatter 生成动态表格/列表 | 按需启用（配合五键规范） |
| git | 版本历史、分支、协作免费获得 | 已启用，改动前 `pull`、完成后 `push` |

## 为什么有效

知识库的痛点不是阅读和思考，而是**维护性簿记**：更新交叉引用、同步摘要、标记矛盾、保持几十页一致。人类因维护成本增长快于价值积累而放弃 wiki；LLM 不会厌烦、不会漏改、能一次改 15 个文件。**维护成本趋近于零，wiki 就能活下来。**

> 理念源头：Vannevar Bush 1945 年的 Memex——私人、主动策展、文档间的关联与文档本身同等重要。他没解决的问题是"谁来做维护"，现在由 LLM 接手。

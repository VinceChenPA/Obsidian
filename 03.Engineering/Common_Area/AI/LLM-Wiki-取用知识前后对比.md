# LLM Wiki 前后：取用知识的区别

> 引入 LLM Wiki 工作流前后，从知识库**获取知识**有什么不同？核心：从"每次现检索原料"变为"读已编译好的页面"。

## 对比总览

| 维度 | 引入前（传统检索/RAG 式） | 引入后（LLM Wiki） |
|---|---|---|
| 取用路径 | 每次提问 → 全库找片段 → 现场拼合 | 先读索引（Home → MOC）→ 直达已综合好的页面 |
| 答案形态 | 碎片拼接，依赖当次检索命中 | 页面已含交叉引用、矛盾标记、更新后的综合 |
| 结果稳定性 | 同一问题不同时间可能拼出不同结果 | 稳定，读的是同一份被维护的 wiki |
| 成本 | 每次重新理解原始文档 | 知识编译一次，反复读取成本低 |
| 积累性 | 问答留在会话里，下次从零再来 | 好答案归档回 wiki（Query），越问越厚 |
| 新旧信息冲突 | 多篇说法不一，现场临时判断 | ingest 时已更新/标记（"已被 XX 取代"） |
| 人看的东西 | 原始文件堆 | MOC 索引 + 图谱，可见知识全貌 |

## 本库实例：问"TAVR 和外科手术的区别？"

**引入前**
1. agent 翻找 `05.Health/心脏瓣膜病/` 原始笔记；
2. 现场拼凑回答；
3. 答案用完即弃，下次再问重新拼。

**引入后**
1. 沿 `Home.md → 05.Health/MOC.md` 直达 4 篇已互链笔记，读整理好的内容作答；
2. 答案有价值时询问是否归档（Query），写回 wiki；
3. 矛盾与缺口由 Lint 周期性暴露。

## 一句话总结

以前知识库是"档案室"（存材料，取用靠检索）；现在是"编译车间"（存加工品，取用读成品，且每问一次可能多一件成品）。

# 待办工作流

本库的待办机制由三部分组成：模板 [[Templates/todo_template]]、唯一活跃清单 [[todo]]、以及本页描述的日常/每周节奏。规则同样登记在 `AGENTS.md` 的「待办清单」约定里，本页是可读的完整版。

**一句话原则**：[[todo]] 只放「动词」——能立刻开始的动作；任何「名词」（想法、素材、结论）都放别处。

## 每日循环（约 2 分钟）

**① 捕获** — 想到就写，不归类、不纠结放哪：

```markdown
- [ ] 给 QMT 回测加滑点 ｜ P2 ｜ [[06.Personal/量化/QMT]]
```

- 30 秒内写完；优先级缺省 P2，截止日期缺省不填（只填外部约束：会议、交付、行程）
- 标题要能由别人照着执行：「优化一下策略」不行，「给 QMT 回测加滑点参数」可以

**② 分诊** — 每天开工前从 `## 待办` 挑 1–3 条挪进 `## 进行中`。进行中区的条数就是「今天要做的事」，超过 3 条说明分诊失败。

优先级含义固定：P0 = 今天必须、P1 = 本周、P2 = 该做但不急、P3 = 有空再说。

**③ 执行与归档** — 做完就挪行，不要只改复选框：

```markdown
## 归档
- [x] 给 QMT 回测加滑点 ｜ P2 ｜ done 2026-11-11
```

放弃的任务同样进归档，标 `❌` 并写一句原因（「❌ 方案已废弃：券商接口不支持」）。归档区是唯一的「做过什么」事实来源，不删行。

## 每周循环（约 10 分钟，固定在周日）

1. 扫 `## 归档`，上个月以前的条目折叠或清理（值得留的结论此时应已写进主题笔记）
2. 查逾期：`## 待办` 里截止日已过的条目 → 立刻排进 `进行中`，或砍掉
3. 查僵尸：连续 3 周没动过的 P2/P3 → 降级或删除（删除比留着更诚实）
4. 查重复：同一件事换措辞写了两行 → 合并
5. 清单全空 → frontmatter 改 `status: done`，再启用时改回 `active`

## 自动化（DSH 定时任务）

每周循环由 DSH 定时任务代跑，人只看报告、拍板动作。

| 项 | 值 |
|---|---|
| 任务 | 待办清单周复盘（id `schedule-14e0ae00-…`） |
| 节奏 | 每周日 20:00（Asia/Shanghai） |
| 投递 | 新会话（不打断主对话），报告在该会话里 |
| 当前模式 | **dry-run**：只读、只出报告，不写文件、不 commit |
| 检查项 | 逾期 / 疑似重复 / 僵尸候选（无截止+无关联+P2/P3）/ 归档清理 / 空清单与进行中超 3 条 |
| 失败策略 | `git pull --ff-only` 失败即停，不碰任何文件 |

**从 dry-run 切到写模式**：让代理改 prompt（允许改 `todo.md`、追加 `log.md`、commit + push），约定不变——git 冲突先停、删除类动作先在报告里列出再执行。

**尚未建**：晨间分诊（每日 08:00 挑 1–3 条进 `进行中`）。等周复盘的判断稳定两周再加，否则等于每天让别人猜「今天要做什么」。

## 溢出规则：什么时候另建清单

| 条件 | 做法 |
|---|---|
| 单步、能一句说清 | 留在根级 [[todo]] |
| 多步骤 / 跨周 / 需要记录过程 | 在 `06.Personal/` 建 `todo-<项目>.md`（用模板），根级只留一行指向它 |
| 已有主题笔记会自然承载 | 写进该笔记的「行动项」，不重复进 todo |

判断标准：**拆成 5 个以上 checkbox 就该独立成文件**，否则根级清单会变成第二个收件箱。

## 和其他文件的边界

| 手上的东西 | 去处 | 理由 |
|---|---|---|
| 要做的事 | [[todo]] | 待执行动作 |
| 想法 / 链接 / 待读素材 | [[quicknote]] | 待消化，非动作 |
| 外部原文 / 报告 | `98.Raw/` | 不可变来源 |
| 任务中得出的结论 | 对应主题笔记 + wikilink | 任务会归档，结论要留 |
| 当天发生了什么 | `00.DailyLogs/YYYY-MM-DD.md` | 记录，不是计划 |

不与日志自动联动：需要看今天做什么时，手写 `![[todo#进行中]]` 嵌入。多一处自动同步就多一处会坏的地方。

## 交给代理的口令

| 说 | 代理做 |
|---|---|
| 「加到待办：XXX」 | 按格式往 `## 待办` 追加一行 |
| 「今天做 XXX」/「把 XXX 挪到进行中」 | 移行 |
| 「XXX 做完了」 | 移进 `## 归档`、勾 `[x]`、补 `done 日期` |
| 「清理待办」/「复盘一下待办」 | 执行每周循环五步 |
| 「检查知识库」 | Lint 时顺带查过期截止、重复条目、进行中超 3 条 |

## 反模式

- 在 todo 里写多段说明（那是笔记，不是待办）
- 每个项目都建一个 todo 文件（清单碎片化，最后哪个都不看）
- 只勾 `[x]` 不挪行（归档区失去「做过什么」的意义）
- 用 `- [-]`、`- [~]` 这类自造语法（Obsidian 不认，破坏搜索）
- 指望 Daily Log 自动带出待办（没有配套插件，不为它引入依赖）
